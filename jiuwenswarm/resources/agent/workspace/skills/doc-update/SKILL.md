# 文档更新

按用户请求核对文档，交付可追溯的修订或审查结果。先沿仓库的文档路由定位
当前权威和目标文件；从请求、相关改动和现有文档结构推断合理范围。只有缺失
信息会实质改变范围或已接受设计时才询问，继续处理不依赖答案的部分。

## 判断依据

- 源码、测试与 Git 用于核实当前实现；用户要求、已接受设计与政策决定预期
  行为。二者不一致时记录差距，不把缺陷改写为设计要求。
- 区分配置文件原值、运行时解析值和环境变量；按文档主题说明对应层次。
  注释与实现冲突时核对实际使用路径。
- 保留有用途的版本、日期和历史证据。只有已经失效且与当前文档无关的标签
  才删除；不要抹掉兼容性或发布边界。
- 多语言同步遵循项目约定和本次范围。已有对应页面一起核对；缺失翻译先
  记录。用户已要求补齐时直接完成；否则不要扩展成全站翻译工程。

## 修订

定位主题相关的源码和文档，按需要分段读取。核对路径、命令、配置项、默认值、
枚举、能力边界与来源引用。修改目标文件的错误，按项目编号约定更新受影响的
后续章节和入站链接。批量替换前确认精确匹配范围，避免误改表格或相同数字。

审查请求只返回发现；更新请求完成已授权的修改，不把同一范围再次变成审批。
跨模块设计决策或实质扩大范围时说明具体分歧。

## 完成

检查差异、变更处及受影响的标题/链接，确认所要求的语言对应关系。使用仓库
规定的文档检查；文档修订不证明产品行为或验收通过。最终简要列出改动、核对
依据、检查结果和仍影响本次请求的缺口。
