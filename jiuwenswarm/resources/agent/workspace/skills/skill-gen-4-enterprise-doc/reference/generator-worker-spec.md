# 目标技能生成规范

用于将已获取的 SOPStructure 与 raw_text 起草为技能。输入提取见 [结构化提取](sop-structure-pipeline.md)，路径/导入见 [操作说明](operator-playbook.md)。

## 保真与可执行性

用户提供的流程、角色、输入、输出、审批条件、例外和事实优先；将这些要求变成未来 Agent 可执行的操作与完成条件。步骤之外的政策/知识规则不能为了统一格式强行改写成流程。

正文明确用户输入、处理方式、标准交付物和验证边界；章节名称与数量按任务需要选择。来源指定 spreadsheet、表单、工单或报告时保留格式、字段、币种及验证要求；来源未指定时只作保守推断，并标明假设。不要把一个例子扩成所有任务的产品政策。

## 技能结构

SKILL.md 从 YAML frontmatter 开始，name 为与目标目录一致的 kebab-case，description 简述真实能力和触发条件。保留必要 compatibility 等元数据，不用冗长关键词串或“即使只提到”扩大触发。

入口包含共享约束和模式路由；长命令、模式专属步骤、字段表或样例放在 reference/，并说明何时读取。scripts/ 仅在重复或确定性操作确有价值时生成，不为凑结构创建空目录或样板文件。

## 来源与完成

对照结构化对象及其 raw_text，检查关键数字、角色、分支、例外和交付物未丢失。生成技能加入 Source and provenance，解释真实来源；意图路线始终标记暂定，并保留 intent-sop-snapshot.md 的警示与逐字 raw_text。

按实际风险验证：元数据与引用应有效，新增脚本须有相关行为验证，复杂流程可用代表性场景审阅。纯文字整理不自动要求压力测试、全套产品测试或固定数量的评审轮次。验证不授权外部账户操作、真实业务提交或修改原始资料。

写入 skills-draft 后，任务要求可用技能且导入能力存在时完成 skills.import_local。导入失败可交付已验证草稿并说明“未安装”；未经证据不报告可加载成功。只在用户授权覆盖既有同名技能时使用 force。
