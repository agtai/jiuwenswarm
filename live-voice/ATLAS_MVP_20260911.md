# Atlas local Live Voice integration

The user authorizes voice directly in Atlas's existing chat and has selected
the local `live voice hx` repository on `hx/0812_live_voice_w3`. This isolated
worktree starts at `537c5d2c9fc595fe38b2ccd1f93b8984fce594a3`.

Client boundary: extract the existing notification classifier from the React
panel, retain its original exports for compatibility, expose a small headless
Native client using the existing P1 audio, P2 activation and
presentation owners. Ship the existing AudioWorklet with an explicit resource
URL. Atlas owns its chat UI; no embedded or hidden Swarm page is involved.

Risk: extraction Tier 0; client lifecycle Tier 2. Focused existing classifier,
activation and audio tests, added lifecycle tests and package build/typecheck
cover positive startup/close, failed startup, stale completion, single input
submission, real presentation receipts, interruption and resource teardown.
One independent review closes the coherent module. Deterministic checks do not
replace microphone/Provider/user acceptance.

External business routing and host admission are Tier 3 and
must retain existing Native admission and scope checks. Atlas-bound requests
must never fall back to the Swarm executor. No remote deployment, new AgentCore
execution API, task database, multi-session recovery or voice approval is in
scope. Atlas-mode legacy unified text submission is rejected; text remains in
the original Atlas chat entry and the same business observation adapter.

Independent review found and led to fixes for early continuation observations
and stopping while microphone permission remains pending. Loopback HTTP tests
and Native router tests verify exact binding, accepted vs completed state and
zero Swarm executor creation. The package test checks missing/foreign host
confirmation closes P2 before allocating media. Existing Native/audio 164-test
regression passed after the classifier extraction.
