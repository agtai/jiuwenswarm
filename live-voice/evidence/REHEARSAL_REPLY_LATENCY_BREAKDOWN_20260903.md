## 测量边界

用户关心的是最后一个语音音素结束到扬声器第一个可听声音。本次日志未保存这两个物理时间点。
`agent.log`、`gateway.log`、`web.log` 中也没有本次的 `tts_request`、
`provider_first_audio`、`browser_eot_receipt` 或 `webaudio_actually_started` L0 记录。
因此不能声称已经测出了逐轮实际首音，不能把下表合计或聊天时间戳当成实际首音延迟。

可重建的区间是服务端记录 VAD/EOT 到随后语音下行连接建立。后者的普通日志没有响应 ID，
这里只按同一会话的前台呈现与连接时间顺序关联，不能赋予精确响应绑定的测量信用。
网关上行 `first_frame` 是麦克风帧，不是扬声器首音；presentation ACK 也不是首音时间。
各端均在同一台机器，下面使用本地时间 UTC+02，未做独立时钟校准。

完整口径是：**停话到服务端 EOT（未实测） + 下表可观察区间 + 下行连接到实际首音（未实测）**。
源码 `ServerVadConfig.silence_duration_ms` 为 1200，默认和插话识别均沿用；这是静音判定配置，
不是本次每轮实际端点耗时，也不包含音频上行与 Provider 事件传播，不能直接补进实测总数。

## 已确认原因与仍缺少的细分

1. **资料分析的主要成本在 Agent。** final 2 有三次前台模型调用、两次工具调用，最终输出 949 字符。
   Agent 起始到释放为 9.320 秒；首次模型输入 24300 tokens、33 个工具，第三次 26332 tokens。
   Runtime 在 `chat.final` 才创建可呈现 TEXT；前面输出的增量不是可播报单元，所以仍要等整段完成。
2. **A/B 的主要额外成本在生成之后。** A 释放到文字呈现为 8.406 秒，B 为 9.552 秒。
   A 的这个区间重叠 7 次 notification RPC，B 重叠 5 次。A 有一次 RPC 在
   14:40:21.247–26.938 耗时 5.691 秒；B 在 14:41:12.862–19.805 耗时 6.943 秒。
   B 后续还有两次约 0.55 秒的再轮询间隔，符合当前有条件的 500ms backoff。
   不能把这些 RPC 全部时长相加到 F：首个 RPC 与生成重叠。日志没有其内部锁等待/进度排空计时，
   尚不能断言 8–10 秒由某一把锁或某一个 await 独占。
3. **短问题仍走完整两层处理。** 语义模型需要约 1.1–2.1 秒，随后还有 Agent。
   “收到”的 Agent 只有 2 个输出 tokens，却带了 26619 输入 tokens、33 个工具；
   两次模型间的准备、通知、音频启动累加，使这条可观察区间仍为 6.664 秒。
   A/B 回执工具已禁用，各自 Agent 输入为 5466/6048 tokens，输出 48/38 tokens，
   不能说本次回执还在等待一个长思考模型。
4. **音频已有流式下行，但回答文本没有增量播报。**
   `start_product_streaming_synthesis()` 先取得 Provider 第一块音频，再发媒体票据；
   G 因此包含正常流式路径的首次音频准备以及前端交接/连接，不能当作纯 TTS 推理。
   改“整段回答准备后才启动 TTS”需要的是前台回答分段呈现，不能笼统描述为“打开流式 TTS”。
5. **采集停滞属于另一个问题。** final 8 回答之后的分钟级无新采集连接，以及识别退出/超时，
   不能加到 final 8 的模型计算中。具体前端持有者仍按此前诊断保持未证实。

## 按收益和改动量排序的优化建议（尚未实施）

1. 首先定位并移除 A/B 已生成回答后的阻塞：给确切通知 RPC 的授权、共享锁、任务进度排空和
   队列获取加短期分段计时；已准备好的当前前台回答应避免被无关进度处理阻塞。
   已有 observer 批量机制应保留并正确使用；不要重建一套协议，也不要删除权威检查、ACK 或去重。
2. 缩减隔离前台 Agent 的无关提示词/工具上下文，保留任务能力；复用安全的静态准备，
   每轮继续核验授权。简短对话和权威回执保持简短，用自然表达验证，不能按 Demo 句子套答案。
   若进一步合并语义和回答调用，应先明确该行为/权限边界，不将其作为无风险开关。
3. 对资料分析先得到有依据的一两句可播结论，详情留在文字或后续回答。
   真正增量播报需要明确可呈现分段及打断/迟到输出隔离，是更大的后续改动。
4. 先处理上述多秒开销，再小幅调 VAD 静音门限；1200ms 直接降低会增加自然停顿误切句，
   需少量长句停顿/插话样本验证。复用音频连接也必须保留旧代关闭与新代隔离。
5. 最小度量复用现有 L0：只采三类短样本（简短答复、创建回执、读文件），记录最后非静音输入、
   EOT、final、各模型起止、回答就绪、通知到达、TTS 请求/首块、浏览器首个非静音播放。
   浏览器数字首音与扬声器物理首音仍分别标注，不用完整 Demo 或完整测试套件来补这项度量。

这些建议没有构成稳定几秒首音或完整预演通过的证明。诊断其他功能问题见
