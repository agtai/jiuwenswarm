# Realtime 六项修复、启动补修与统一验收

基线为 `af6a5bbb0cadd0e260e12961ee33f737db489d31`，原有十二个提交保留。
Main 在独立工作区完成集成；三个 worker 分别承担生命周期、项目执行、音频，
关键生命周期交错由独立 Astra 复核。六个修复点各形成一个本地 commit，
由 Main 合入 `hx/0812_live_voice_w3`，不更新远端。实际启动验证又暴露一个
既有启动生命周期缺陷，单独作为第七个修复提交，保留前六个提交。

## 修复内容

| 修复点 | 提交 | 行为变化 |
| --- | --- | --- |
| R1 输出预算 | `aabb52f8` | 默认 `max_output_tokens=inf`，使用模型允许的上限；session 和三条 response 创建路径一致，仍可配置合法有限值。正常长回答不再被旧 1024 上限截断。 |
| R2 生命周期 | `cdaf6cc9` | 区分生成结束、媒体交付、实际播放结束；已生成的尾音仍有精确 owner。Provider reader 不等待音频队列排空，输入/STOP 与后续响应不会因此互相阻塞。 |
| R3 故障尾音 | `3393ba8b` | 明确 Provider 传输故障只冻结并播放故障瞬间浏览器已接受的有限 PCM；停止、退出和重启立即撤销旧音频。不会把残缺回答提交为完整已播放。 |
| R4 正常打断 | `8c748d8b` | 正常取消、替换预备回复不再生成失败消息；Native 真故障放在简短状态提示和折叠详情中，原回复保留被打断状态。 |
| R5 项目与任务 | `ae4b3233` | 接受授权项目中的已暂存、未暂存和未跟踪文件，以当前快照执行，只回写任务增量。A→AA 的条件与保留 A 要求放入同一任务；已知运行任务状态独立于语音定时刷新。 |
| R6 开头与连续性 | `9797b139` | 用实际收到的 PCM 建立有界起播/恢复储备，完整结束的短句及时 flush；不重复创建已启动音源。Gateway 用单一持久 reader 按原序处理有界 ACK 批次，保留 STOP 优先级。 |
| R7 启动补修 | 本次启动修复提交 | Native 首次连接最多等待 15 秒；启动中的会话在异步操作前登记，取消后即使 Provider 迟到成功也不能复活旧会话。旧启动真正结束后才关闭其 Engine，清理未知时保留有界占位。 |

提高输出预算并不能代替生命周期修复。即使没有命中上限，网络故障、正常取消、
生成失败和后续回复重叠仍可能经过这些边界，因此 R2/R3 都保留独立修复。
R6 修复了已证明的局部等待与缓冲算法问题；整体延迟和真实听感仍需当前设备验收。

## 启动补修的独立边界

六项候选的实际构建、端口、产品注册和 Speech 探针通过后，指定 Chrome 页面
仍在三秒时因 `AUDIO_CAPTURE_MEDIA_ROUTE_NOT_ATTACHED` 退出。Provider 随后才
连接成功，旧启动却被重新登记，导致重复恢复报 `MEDIA_NATIVE_SESSION_ALREADY_ACTIVE`。
原始失败证据保留；基础服务启动通过不等于 Live Voice 已进入聆听。

R7 只调整 Native 初次连接预算，保留 Cascade、下行、首帧和 ACK 的原有期限。
前端最终相关检查 21 项与完整 Native mounted 组 26 项通过，含真实四秒延迟。
后端启动过程的取消、替换、过期、清理与实际 socket 检查以及独立复核见
[启动修复记录](REALTIME_NATIVE_STARTUP_REPAIR_20260907.md)和
[后端证据](REALTIME_NATIVE_STARTUP_BACKEND_20260907.md)。最终服务与页面状态以
重新部署后的本地运行合同、诊断和实际聆听状态为准，仍不替代听感与任务文件验收。

## 用户统一验收

只使用指定页面 `http://localhost:5173/chat/web_1a07c19956f_46525241c42b`。
部署后刷新，开启 Live Voice，沿用原模型、项目和设备。原文件和已有任务保留。
首先确认状态进入“聆听中”，退出后再次开启也能进入聆听，没有反复恢复。

1. 重问原来的费用/出发时间比较，要求完整列出两个方案和最终建议。
   检查文字末句完整、语音能播到结束，没有在“850 元”附近停止并报传输失败。
2. 在较长回答播报中说出新问题，连续做三次。旧回复应保留被打断状态，
   不再新增“本次回复未完成（NATIVE_PREPARED_RESPONSE_INTERRUPTED）”消息。
3. 在现有文件尚未提交的项目中明确要求创建一个不存在的文件，例如 `b.md`。
   然后要求以它为基础保留源文件、调整指定条件并保存到另一个明确文件名。
   检查实际文件与要求一致，任务完成状态自动更新，不要求先清空整个工作区。
4. 连续提问至少五次，混合短回答和长回答，重点听每句开头、数字、转折处。
   若仍有断裂，记录对应回复/发生位置并导出页面诊断；录音可帮助区分源音频
   缺陷与实际设备播放问题。自动检查不能代替这项听感验收。
5. 正常使用停止播报、退出和重新开启；旧音频不得恢复或重复播放。
   传输故障保留尾音的场景已做确定性注入检查，无需人为断网验收。
